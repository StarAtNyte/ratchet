# <op> — operator workspace contract

One directory per operator, shared by the outer meta loop and the inner student loop.

## Layout

What the scaffold creates (`forge init <op> --kernel-file ...`):

```
operators/<op>/
  README.md                  # this file: target / shapes / where the reference source is (a pointer; the student must not read it)
  submit.toml                # which machine the jobs run on (forge run writes it from local.env: this machine or one ssh host)
  submit.local.toml.example  # configuration that must not be committed (e.g. the sealed reference's key) goes in submit.local.toml
  agent/                     # operator-specific copies rendered from meta/*_prompt.md
  .gitignore
```

What the operator author adds afterwards, or the loop produces itself:

```
  kernel.py                  # author-written: the only file the student may change; its signature is frozen at M0
  gpu_entry.sh               # author-written: GPU job entry point, dispatches correctness / perf / ncu
  eval/                      # author-written: bench, ref baseline measurement, NCU collection, self-test
  loop.toml                  # author-written (gitignored): oracle path, implementation language, how the ref runs
  ref_baseline.json          # forge <op> baseline archive: the ref's measured values, taken before distillation
  milestone.md               # written by the meta loop's distill step, refined in place by the patch step
  student/status.jsonl       # inner trajectory (the driver appends one record per round)
  meta_status.jsonl          # outer trajectory (one record per meta step)
```

> **Trees generated from a task.** When a run's operator tree is generated by `forge run` from
> `tasks/<op>/task.toml` (see `src/forgekernel/taskcard.py`), nothing in it is written by hand: the
> kernel stub (`kernel.py` / `kernel.cu`), `gpu_entry.sh`, `eval/`, `window.toml`, `submit.toml` (from
> `local.env`) and `loop.toml` are all generated, and `loop.toml` / `submit.toml` are rewritten on
> every launch. To change them, change the task (or `local.env` for the machine) and re-run
> `forge run`, rather than hand-editing the generated files. The sections below document what these
> files contain and which keys the loop reads; where they say "the author writes" or "declare in
> loop.toml", for a generated tree that is what `forge run` does from the task.

> How to write a milestone: [`docs/milestones-template.md`](../../docs/milestones-template.md);
> the machine-read skeleton: [`meta_milestone.md §9`](../../meta_milestone.md) (the one `validate_milestone` checks).

## Required fields (see each operator's own README)

- **target**: not filled in by hand — `forge <op> baseline` measures the ref and archives it, the loop
  converts it into the stop threshold by the equivalence ratio, and the teacher writes it into the
  machine-read `target_ms:` of milestone §0 during distillation.
- **equivalence criterion**: by default, reproduce ≥95% of the ref's throughput (`--equivalence-ratio`)
  + pass correctness.
- **shape A / shape B**: A is used for the inner iterations; B is a coverage probe — acceptance is
  checked on B, but a failure on B does **not** invalidate the milestone; it only shows that "the scope
  does not include B", and if needed a separate milestone is written for B.
- **reference source location**: the original operator's source path, readable only by the
  meta-agent (teacher); **the student must not read it** (L0).

## eval/bench timing contract: both windows must be reported

The same kernel reads differently under the two timing windows (the same cuDNN attention: e2e 0.28ms
vs device 0.25ms), and the two sides of a ratio can pay different host taxes — so the bench **must
measure and report both windows**, using `eval/timing.py` (copied from `_TEMPLATE/eval/`; do not edit it):

- **e2e** (per-call + sync, includes the host tax) → perf JSON keys `bwd_median_ms`, reference
  `ref_median_ms`, ratio `vs_ref`;
- **device** (pipelined amortized ≈ pure device) → `device_median_ms`, `ref_device_ms`,
  `vs_ref_device`.

**Single-ref contract**: the `ref_*` keys may hold only one thing — the reference declared in this
run's loop.toml, timed back to back in the same job. In a run whose reference cannot enter the
student job (blackbox: the reference package is readable source), the bench **measures only the
student and emits no `ref_*` key**; it is forbidden to run any stand-in library alongside "to
calibrate node speed" (the retired "ruler" concept — it made every vs_* number ambiguous; a
same-job 1.0418x was once read as "overtaking FA" while the denominator was actually cuDNN; the
driver now loudly discards such readings). A run with no ref alongside compensates for noise with
repeated measurement: in the finish confirmation phase the best and the reference are re-measured,
each through its own channel, median against median.
(parse_eval still recognizes the `cublas_*` key names of old benches as aliases.)

**When the reference rides the job (`ref_in_job = true`) you must use `timing.measure_paired`** to
take both sides' readings and `timing.paired_performance` to map them into the perf JSON; **two
back-to-back `measure_windows` calls are not allowed**. A same-job ratio is fair only when both sides
sit on the same thermal plateau: a job's first timed window is the fastest (cold card, full boost),
and after that it drifts slowly with temperature — the same kernel measured first as "kernel" and
then as "ref" can differ by 2–5%, all of it landing on the side measured first. `measure_paired`
first burns the card with the kernel under test for a few seconds (burn-in), then measures in the
mirrored order **ref, kernel, kernel, ref**, each side's device value being the mean of its two
readings; if the reference is absent or throws, the kernel reading is reported as usual and no
`ref_*` key is emitted (single-ref contract). The tighter the target (an equivalence bar of ≤5%), the
less this step can be skipped.

**When the reference is source rather than a library** (e.g. the reference is a `kernel.py` produced
by an earlier run), do not put the plaintext into the operator tree — use `eval/closed_ref.py`
(copied from `_TEMPLATE/eval/`; do not edit it) to seal it into an opaque payload at
`eval/ref_bin/ref_payload.bin`; in the bench, `closed_ref.entry("<entry name>")` loads it in memory and
hands back only a callable. The key goes in each tree's gitignored `submit.local.toml [env] FK_REF_KEY`
(the agent policy refuses that file to the student / blackbox teacher: the key is inside the run, and
what stops unpacking on the driver machine is the read refusal, not the ciphertext — do not put the
key in any other file). The key must not stay in the job environment (`cmd` probes and the student
kernel would inherit it): right after `set -euo pipefail`, `gpu_entry.sh` follows
`forgekernel.sealref.key_preamble()` to move the key into `ref_bin/ref_payload.key` (600, added to
.gitignore) and re-exec itself without it; `closed_ref` reads that file when the environment has no key.
Before starting, run `python eval/closed_ref.py check-tree <tree/ws path> eval/ref_bin/ref_payload.bin`
to confirm the tree holds no reference plaintext; add `closed_ref|ref_payload` to the bench's
`_FORBIDDEN` regex, and add these two names to `BLACKBOX_EXTRA` in the reference tree's `gpu_entry.sh`.
A multi-file solution (`sources` of a solution JSON, or a directory) is sealed into one bundle with
`seal solution.json` / `seal <dir> --entry k.py::run` and loaded in the job as an in-memory private
package (relative / absolute imports between its files map into the package); the source is visible to
the JIT only while loading and during calls through `entry()`, and exceptions thrown by the reference
keep only their type and `file:line`. A leaderboard tree needs no hand assembly:
`forge init <op> --leaderboard ... --sealed-ref solution.json` generates the tree, the reference tree,
the key and the fence in one go (`forgekernel.sealref`).

### Performance is judged on the geomean of 3 workloads

An operator tree fixes one shape, but **performance must not be measured on a single input**: timed
on one input only, the kernel's partitioning, per-CTA work assignment and assorted constants all
fit that one point. Re-measurement showed that a kernel at 1.05x on its tuning point can drop to
0.66x on other workloads of the same shape; data-dependent speculative fast paths fall back
wholesale on value distributions that were never measured.

So the bench uses `timing.measure_windows_workloads` to run one mirrored paired timing against the
reference on each of **`PERF_WORKLOADS` (3)** representative workloads, then
`timing.workloads_performance` to map them into the perf JSON:

- **The top-level keys are unchanged** (`device_median_ms`, `bwd_median_ms`, `ref_device_ms`,
  `vs_ref_device` etc.); their values are the **geomean** over the 3 workloads — the ratio of the two
  sides' geomeans is exactly the geomean of the per-workload ratios, and the driver's best / plateau /
  target / confirmation / re-anchor / patch ruling / pricing all read this aggregate directly;
  `host_bound_ratio` takes the worst workload.
- Additionally report `aggregate = "geomean"`, `n_workloads`, and `workloads`: one
  `paired_performance` reading per workload (with `name`). The driver shows them per workload in the
  KEEP log, the teacher digest and `best_confirmation.json`.
- If any workload lacks a reference reading, **no `ref_*` / `vs_*` is emitted at all** (a ratio over
  a subset quietly changes the weights).

How to pick the 3: **cover the real variation of that shape**, not the same distribution with another
seed. Variable-length operators take different sequence splits at the same token count (campaign,
the heaviest, the most skewed); sparse operators take different index tables; dense operators take
the campaign distribution plus two value distributions (sharp logits, a dominant sink key, key
magnitudes increasing along the sequence, real activations). **The first must be the campaign
workload**: `eval/ncu_run.py` profiles only it, and correctness replays it first; all 3 workloads must
also appear in `correctness_cases()`.

**Reference on the same basis**: the absolute target, the cross-cluster scale and the finish's
median-vs-median ratio all divide a gate reading by the archived reference reading, so the reference
must also be the geomean over **the same set of workloads**:

- the reference measurement script of `ref_cmd` reports the `workloads_performance` geomean block
  over these 3 workloads (with `aggregate = "geomean"`, `n_workloads` and each workload's `name`; the
  archive accepts only this block, and records which workloads it covers);
- if a hand-filled `arch_ref_ms` / `arch_ref_device_ms` is the geomean over these 3 workloads, list
  the names in `[loop] arch_ref_workloads = ["<name>", ...]`; otherwise it counts as a single input;
- on a basis mismatch a fresh start is refused (exit 17) and a resume only warns, while the driver
  disables the absolute target (no stop on it, no re-anchor on it, no book residual reported); the
  same-job ratio is unaffected. An existing single-workload archive has to be re-measured
  (`forge <op> baseline --force --ref-cmd <ref_cmd>`).

**Trees with a prep step**: the prep function receives the workload name — `def prep_saved(workload): ...`;
`measure_windows_workloads(..., prep=prep_saved)` calls it once per workload, and each workload's
timed call gets tensors computed from **its own** inputs; `workloads_performance` reports one `prep`
block containing one entry per workload, and the driver checks each against window.toml.
`eval/ncu_run.py` calls the same function with the campaign workload's name. A zero-argument prep is
refused (it could only close over one workload's inputs).

Ratios may only divide within the same window: an e2e ratio is a **call-latency** claim, only a
device ratio is a **kernel-to-kernel** claim; the two must not be mixed, nor converted and then cited
as measured. The ref measurement script (`ref_cmd`) must report both windows too (the archive
recognizes any of the device key names `device_median_ms`/`device_ms`/`ms_device`) — otherwise a
run with gate_window = "device" is refused at start.

### The device window has a precondition: the host must be faster than the device

The device window holds only if "the host enqueues faster than the device drains", so the pipeline
stays full. This is a **precondition, not a conclusion**: once the measured side's per-call host
overhead approaches its GPU time (the typical case is a library with a **thick python shell + a light
kernel** — validation, dispatch and logging decorators all count), the pipeline cannot be kept full,
the GPU idles, and the device reading measures the host's dispatch cost dressed up as device time.
Such a reading passes correctness, reproduces across jobs and cannot be explained away as node noise:
**not one of the existing defences stops it**.

So `timing.py` carries a built-in precondition self-check, and the bench must report it:

- `host_enqueue_ms` — measures host enqueue only (N back-to-back calls, no sync in between), pure
  python + launch;
- `host_bound_ratio` = `host_enqueue_ms / device_median_ms`. Far below 1 when GPU-bound;
  approaching 1 means host-bound, and then the device reading is not a reading of kernel quality.

The default threshold is 0.5 (`HOST_BOUND_RATIO_WARN`). Both keys must be in the perf JSON — the driver
parses them, writes them into `student/status.jsonl` and warns on them; not reporting them means this
check was never executed.

**What to do when the reference is a thick-shell library** (once the check trips, it is handled per
measured side, and the right reaction on the two sides is opposite):

- **Host-bound on the reference side = a problem of the measurement layer.** It is not a fact about any
  kernel, and the student should not react to it (telling someone who writes kernels "the reference's
  python shell is thick" teaches them "make the python path thinner and you win" — that is gaming the
  metric, not building a kernel). The right move is to re-measure the reference on a host-free basis
  and derive the target from that: `measure_windows_with_graph()` in `timing.py` (CUDA graph replay,
  host cost goes to zero; a failed capture or an empty captured graph is explicitly judged unavailable
  instead of yielding a fake number), or the reference's total NCU kernel time. The archive's
  `device_window_basis` records which window this device number was actually measured with. If no
  host-free reading can be had, **the start is refused** — a whole run against a target inflated by
  the host tax produces conclusions that cannot be cited.
- **Host-bound on the student side = a real performance defect** (recompiling / JIT on every call,
  python-side allocation, extra launches, synchronization inside the call), and it inflates the
  student's own reading and is paid at deployment too. The driver feeds it to the student as a
  diagnosis to fix in the next round.

Likewise, **NCU reconciliation** (the profiled kernel time does not fill the timed window) has two
physically different causes: the kernel never made it into the CSV (wrong window sampled), and the
GPU idling behind a host bottleneck. Only `host_bound_ratio` tells them apart, so the driver reports
the two causes separately — but **it only warns, it does not stop**: one NCU sample covers several
bench calls that nobody recorded, so this fraction is a smell, not a measurement.

Which window the loop's gate (best / target stop / plateau / rollback anchor) reads is decided by
`gate_window` in loop.toml below, default `"device"` (the kernel-to-kernel basis; historically,
early runs used e2e); target_ms is always converted from the ref reading of **the same window**, and
milestone §0's `target_ms:` carries a machine-read `target_window:` annotation next to it (seeded and
checked by the driver; on a mismatched annotation the §0 target is refused). If gate_window = "device"
is set but the bench measures e2e and not device (a structural gap), the loop stops with the dedicated
reason `gate_unmeasured` as soon as the first KEEP is recorded — on purpose: a silent downgrade would
let the loop idle until the wall clock runs out; a whole missing perf block (a transient such as the
job being killed midway) is still tolerated as a record without a reading, the same for both windows.

## Timed-window content contract: what each side's stopwatch covers (`window.toml`, required)

The two sections above are about "how to time"; this one is about "what work is inside the window".
The reference's timed call and the student's timed call are two different functions, and **every
place where the boundaries differ is a fixed tax that one side gets for free and the other side pays
inside its window**: no kernel quality removes it, and the ratio does not show it. Both directions
count: the reference gets it for free (a backward operator's reference, called through its own
autograd path, consumes the cumsum / in-chunk solve / LSE the forward saved, while the student rebuilds
them from the raw inputs); the student gets it for free (the student's signature directly takes a
derived quantity the reference computes inside its window, produces one output fewer than the
reference must produce, or a reduction or copy the reference does along the way inside its window);
a library with caches has warm caches on its second call.

So the boundary is declared once in `window.toml` (copied from `_TEMPLATE/window.toml` and filled in;
a tree generated from a task gets one from `forge run`), and `loop start` machine-checks it:

- `[reference].inputs / outputs` = every tensor the reference's timed call consumes / produces (with
  the reference API's names); `[student].inputs / outputs` = the frozen signature of the student's
  timed call. All four lists must be filled.
- **Every item that appears on only one side** (the difference of the two inputs lists, the difference
  of the two outputs lists) must have an `[[asymmetry]]`, using one of the four keys `ref_input` /
  `student_input` / `ref_output` / `student_output` according to which list it appears in; whichever
  side does the extra work inside its window pays (`ref_input` and `student_output`: the student pays;
  `student_input` and `ref_output`: the reference pays). `class` is one of three: `symmetrize` (only for
  derived inputs both sides receive; neither side pays), `price` (once the paying side's regex is set —
  `student_kernel_regex` / `ref_kernel_regex` — the finish step subtracts its share from that side's
  per-kernel NCU table and reports the tax-credited ratio), `accept` (the paying side does it and this
  run knowingly bears it; recorded only). `derived_from` names the other side's raw input; a raw input
  named there needs no separate declaration.
- The standard form for a backward operator: the window times only the bwd body, and one prep step
  outside the window may produce the saved tensors (training-step semantics, symmetric with the
  reference's autograd path); these tensors are listed in both sides' inputs and `symmetrize`d.
- **The prep step is the only place where work can legitimately leave the stopwatch, so it is
  machine-checked**: every `symmetrize` item must give `shape` / `dtype` (missing either refuses to
  start). prep is written by the **operator-tree author** in `eval/bench.py` in torch as a module-level
  def — not a lambda, and it must not reference any name imported from `kernel` (the student owns only
  the timed call, not the step outside the window); the bench runs it outside the window with
  `measure_windows(fn, prep=<that def>)` from `eval/timing.py` and puts the returned `prep` block
  verbatim into the eval JSON's `performance`; `eval/ncu_run.py` must import the same def `from bench`
  and call it before `torch.cuda.profiler.start()`. `loop start` checks these three statically and
  refuses to start if any fails. At run time the driver matches, every round, the names / shapes /
  dtypes of the tensors prep actually produced against the declaration, and checks whether the timed
  call rewrote a prep tensor (the same memory is passed to every timed call, so caching state in it =
  later calls just copy; timing.py keeps a snapshot to reconcile): an extra output, a missing one, a
  mismatch or a rewrite = that round fails correctness and is REVERTed; a bench that does not report
  the prep block at all = a structural defect, and the run stops with `prep_unreported`; the same
  mismatch repeated verbatim two rounds in a row = a `prep_contract` stop (the same family as
  `gate_unmeasured`: fix the bench / window.toml, not the kernel). prep's own two-window cost is banked
  every round and rendered to the teacher (not counted in the ratio). `produced_by = "cache"` (a
  library's warm cache) is not a tensor and is not machine-checked.
- **Undeclared or inconsistent → a run with a reference refuses to start (exit 13)**, for the same
  reason an unmeasured device window refuses; `forge <op> window` checks it ahead of time. A run already
  under way (status has records) only warns. `--allow-undeclared-window` is the knowing escape hatch.

The driver renders both sides' per-kernel tables (the reference's from the baseline archive's
`kernels`, the student's from each round's NCU) together with the contract to the teacher
(distillation / recon / M0 audit / diagnosis all get it), and the finish's `best_confirmation.json`
gains a `window_credit`: the share of each side's regex-matching launches, both sides' readings after
the tax credit, and `credited_ratio`. Pricing has two preconditions: the regex must match something in
that side's table (no match after the rebuild is fused into the main kernel or renamed = pricing
**unavailable**, not a share of 0); and the per-call total of that side's NCU table must agree with the
window reading (±20%, the same arithmetic as the mis-aim reconciliation — the tree's
`eval/ncu_run.py` must use profiler start/stop to cover only the timed call; prep and setup launches in
the table dilute the share); if it does not agree, pricing is likewise marked unavailable.
**Stop, KEEP and target still use the raw ratio** — the tax-credited ratio only says how much of the
residual no kernel lever can remove; fusing the rebuild into the main kernel is a legitimate
performance decision and is not constrained for the convenience of pricing.

## loop.toml (gitignored, not in the student's tarball)

For a tree generated from a task, `forge run` writes this file from `tasks/<op>/task.toml` on every
launch (see `write_loop_toml` in `src/forgekernel/taskcard.py`); it is not a place to configure
anything — change the task instead. The keys below are what the loop reads:

```toml
[loop]
oracle   = "/abs/path/to/reference_impl.py"   # the teacher may read it, the student must not
language = "cutedsl"                          # what the student writes the kernel in
kb_arch  = "sm90"                             # which hw_kb/<language>/<arch>/ tree the run reads and writes (sm90 / sm100…);
                                              # default sm90; the tree must exist and have an index.md, else the start is refused
gate_window = "device"                        # which timed window the loop's criteria read: "device" (default,
                                              # ≈ pure device) or "e2e" (includes the host tax);
                                              # target_ms is converted from the ref reading of the same window

# how to measure the ref — declared once; the loop measures and archives it on its first run, then reuses it
ref_cmd     = "python3 eval/measure_target.py"
ref_ncu_cmd = "ncu --csv --target-processes all --launch-count 24 --metrics <…> python3 eval/ncu_ref.py"
ref_name    = "torch-SDPA cuDNN"
ref_shape   = "B=10 H_Q=16 H_KV=2 N=4096 D=64 fp16 causal GQA-8:1"
ref_hardware = "H100"
```

### What an agent can touch (enforced by the harness, `src/forgekernel/loop/agent_policy.py`)

- **The student is always offline**: WebFetch / WebSearch are removed and Bash network access is
  refused by the sandbox (three layers: `deniedDomains = ["*"]`; a `WebFetch(domain:*)` deny rule that
  cuts the network for commands inside the sandbox too; `failIfUnavailable`, so a sandbox that fails
  to come up stops the run instead of silently letting it through); the reference source and the
  teacher-only trees (the recon tree, the reference measurement / pricing tree, a source run's oracle
  **and the directory it sits in**) cannot be read.
- **The student can write only its own working directory**: the rest of the run repository (meta
  prompts, hw_kb, other operator trees, the hook scripts themselves) is not writable; only the teacher
  has write access to the whole repo (it has to land the milestone and KB recipes).
- **The teacher may go online** (docs, forums, papers), but code from the web must not be copied into
  the milestone / KB; **a blackbox run's teacher must not read the reference source** — the local
  checkout of the reference is refused by the sandbox (this one is a hard boundary); on the network
  side there is only the hook as a **tripwire**: it normalizes `:` to `/` and then matches the declared
  fragments and their `org/repo` pairs, so `github.com/org/Ref`, `raw.githubusercontent.com/org/ref/...`,
  `api.github.com/repos/...`, `cdn.jsdelivr.net/gh/...`, `git@github.com:org/Ref` and
  `pip download ref-lib` are all refused, but **a fetch that never spells out the repository name (a
  short link, a second-hand mirror, a script that assembles the URL at run time) cannot be stopped**;
  that still relies on the discipline of the teacher prompt.
- Before every agent turn the driver writes that role's rules into `.claude/settings.json` in the
  working directory (Claude Code project settings: deny rules + Bash sandbox + PreToolUse hook; added to
  that repo's `.git/info/exclude`, a linked worktree goes through the common dir), and states the rules
  at the top of the prompt. So the agent command must run in the working directory and read the
  project settings: an agent leg with `--setting-sources` not including `project` (including an empty
  value), `--bare`, `--settings` (it overrides the project settings), `env -C`, or a `cd` first
  (including `(cd … && claude)`) before starting the agent is refused by the start preflight (exit 15).

Where the reference is, is declared in loop.toml:

```toml
ref_source_paths = ["~/refs/vendor/RefLib"]        # the reference's local checkout / install directory ([] if none)
ref_source_urls  = ["github.com/org/RefLib"]       # URL fragments of the reference's code repository ([] if none)
dsl_source_dirs  = ["~/.cache/dsl-src/cutlass"]    # locally readable DSL package sources, pointed out to the offline student
agent_allow_write = []                             # optional: directories Bash may write besides the working directory and temp dirs (and the run repo for the teacher)
```

**A blackbox run must write out both keys `ref_source_paths` and `ref_source_urls`** (they may be
empty lists): leaving one out makes the policy block nothing, indistinguishable from "there really
is none", so the start is refused (exit 15).
`dsl_source_dirs` may be left empty: a run with `language = "cutedsl"` derives a default directory from
the locally installed `nvidia-cutlass-dsl` (of the interpreter running the loop, or the one given by
`dsl_python = "/path/to/python"`) (`nvidia_cutlass_dsl/dsl_packages/` inside the wheel, i.e. where the
`cutlass` package lives); loop.log prints `dsl_source_dirs: defaulted to [...] (nvidia-cutlass-dsl <ver>)`,
and the dry-run's `dsl_source` line shows where it came from.
The default has two gates: if the local version differs from submit.toml `[env] DSL_PIN`, there is no
default (a warning only; install the same version or declare it explicitly); if the default directory
overlaps `ref_source_paths`, there is no default. With no DSL installed locally it is still only a
warning — the student is offline, so it then has no API source to read at all.

A source run need not write these two keys: `oracle` is the declaration — every file of the oracle
and the directory it sits in are refused to the student (in a reference package the tile shapes often
live in an `interface.py` next to the oracle).

The reference's **overlap ledger** (the role exposure ledger with tensor duty cycle + the PM-sampled
phase timeline) is produced by the driver running the frozen recipe `stall_price_run.py --pm` once on a
teacher-side tree; the distill step and every plateau diagnosis read it.
A blackbox run **uses the recon tree by default** (`ref_price_op` defaults to `recon_op`); a source run
(which has no recon step) has to name one:

```toml
ref_price_op = "_myref"   # the reference's teacher-side submission tree (operators/_myref, a git repo of its own);
                          # for a blackbox run the default = recon_op; writing "" explicitly turns it off
ref_price_app = ["python3", "myref.py", "ncu"]
                          # that tree's profiler-window entry point (opens the profiler only around the kernel call).
                          # May be omitted when the tree has eval/ncu_run.py; with neither, the driver prints
                          # a WARNING in the preflight, and at the end of recon the teacher must add ROLE/PMTL waiver lines.
                          # Every item of the list is passed to the entry point as is; do not stuff recipe flags (--pm-interval) in here
ref_price_pm_interval = 0 # PM sampling interval (cycles), shared by both trees' pricing jobs; 0 = chosen
                          # from the target reading (≥0.5 ms uses 8192, fast kernels 2048 — 8192 gets too few
                          # samples on a fast kernel and PMTL always FAILs). Changing it makes the driver re-price
                          # a reference that lacks only PMTL
```

The driver runs it once at the end of recon (blackbox) or at the first teacher entry (source) (the whole tree is committed before submission — the job archives the branch); when the job brings back no overlap ledger it retries **only after the entry file / `ref_price_app` has changed** (re-running the same tree would only reproduce the same verdict), at most three times;
the output is stored in operators/<op>/evidence/ref_*.txt (for a blackbox run, next to the recon tree).
Without it, the role exposure ledger and the dossier diff have only the student's side — two observed
failure modes: the reference column was a verbatim copy of the student column; and the reference role
table the recon agent collected itself had no tensor entry, the exposed column was null for the whole
run, and several blackbox runs in a row all guessed wrong at exactly the point of "how the reference
hides its operand supply behind the MMA". `evidence/` is a phase product; the freshstart gate refuses
to let a newly launched run inherit the previous run's.

**Pricing round** (plateau diagnosis **and the M0 audit**, on by default): before diagnosing, the
teacher lists up to `lever_pricing_max_levers` (default 5) stackable local levers in
`notes/levers.json`; the driver measures add-one / remove-one / all-on on the best tree in one job with
`notes/lever_pricing_run.py`, and feeds the `LEVER … class=independent|coupled|dependent|null|harmful|unstacked|noop` table to
the diagnosis. `lever_pricing_rounds` (default 3)
is the number of interleaved timing rounds per variant inside the job; `0` turns it off (control
run); a best tree already priced in this run is reused, not bought again.
**A multi-workload tree** (`problem.json` lists `meta_workloads`: the representative + the group's
smallest + largest) buys one pricing job per workload
(`--workload <name>`, 2 timing rounds per workload), and the driver merges them into one table: every
number is a geomean, the noise floor is the floor of that mean, the class is re-derived from the
merged readings, and a lever that is faster beyond noise on one workload and slower beyond noise on
another is judged `shape_split` (not null, and it never closes a phase on its own); the per-workload
readings are attached under the table. The stall / SASS pricing at the teacher entry (including one
pricing of the reference on the same workload) and the timeline probe also run one job on each of the
other two workloads, attached after the representative's readings; when the SASS dossier summary is
identical to the representative's axis by axis it only says "same structure" without listing it again.
Each iteration's NCU, the dossier-diff gate, the segment-ledger alignment, and the reuse and triggering
of the timeline still read only the representative — they have to be comparable over time.
**The teacher decides the combinations**: the base and every add-one are always measured (the floor
every citation stands on); the teacher may write up to 6 subsets in the `variants` of `levers.json`
(a list of lever names + the question it answers); each subset yields one `VARIANT` reading against
the base and can be cited by `priced_by=` / `reopen_price: … via lever:<subset name>`; writing
`"in_stack": false` on a lever measures only its add-one and keeps it out of all-on and every subset
(use it when you suspect it is harmful or mutually exclusive); a subset must not share a lever's name,
and before submitting the job the driver validates the whole table locally with the same rules as the
tool, so a mistake does not burn a job. When a lever is judged `harmful` (add-one negative **and**
removing it from all-on costs nothing — add-one negative but costly to remove is `coupled`), the driver
automatically adds one measurement of "all-on minus the harmful items" (`all-pos`, a second pass
re-measured interleaved with the base and read against that pass's own base), because one harmful
lever skews every `remove` reading and the class column is distorted with it.
(Why: observed failure modes — a mechanical 2N+2 table judged a lever `coupled` but could not say what
it depended on; in one table a lever with an add-one of −17.7% was mixed into all-on, all-on came out at
−9% and the other four remove readings were all negative, so not one class could be trusted.)
The audit runs it too, because structural reopens are decided in the audit: a reopen has to be chosen
against the real prices of the levers it bypasses.

**No reopen without a price** (on by default): an `R1` diagnosis and every `structural` / `split` patch
must carry `reopen_price: <delta> via probe:<path>#<n> | lever:<name> | KB:<entry>`; the driver checks
that the source is a verdict probe actually run in this step (with a reading), a lever in this run's
pricing table (this step or earlier), or an hw_kb entry with GPU certification
(PROBE PASS / [PRICED] / job number); otherwise it bounces the step once
(naming the three pricing routes), and refuses on a repeat: no patch, record `UNPRICED_REOPEN` (on the
audit path the segment continues as usual; on the plateau path the meta step is retried).
`[loop] reopen_requires_price = false` turns it off (control run); it is automatically disabled when
the run has neither a verdict-probe budget nor the pricing round.
(Why: observed failure modes — two audits each pointed at a locus without pricing it, while a few
ablation probes afterwards priced three levers in a few hours; the largest of them was not a row in any
ledger and only showed up after the other two were removed; in the same run the M0 audit inferred the
reference's shadowing window from "where the wait instructions land" and reopened the structure, the
whole set of decisions was redone, and the reopen itself was never priced.
Mechanisms and numbers: hw_kb `gather_producer_lead_stack` / `midchain_stage_wait`.)

**Reopen budget** (default 2): after `[loop] reopen_max_fruitless` consecutive reopen transactions
(including the milestone transactions of `structural` / `split` patches; a patch merged after a HOLD
counts as the same transaction, and a transaction counts only when it closes) all end in
`REVERT_PATCH`, the diagnosis prompt first announces that reopening is closed; an `R1` is bounced once
and refused on a repeat, a `structural` / `split` patch is withdrawn from the
milestone, and both are recorded as `REOPEN_CAPPED` (on the audit path the segment continues as usual;
on the plateau path the meta step is retried). Any
`KEEP_PATCH` (a new best, any patch class) resets the count; additive / KB patches and `INFEASIBLE` stop requests are unaffected.
`= 0` turns it off. (Why: a reopen makes the student re-deliver the whole set of already-delivered
decisions on the best tree; reopens that keep coming up empty spend the iterations on re-delivery, and
the re-delivered readings are often worse than the original tree. Counting by transaction rather than
by patch: a patch re-sent in the same direction after a HOLD should not count as two failures; a cap
of 1 would block the case "one reopen came up empty and the next one brought a new best".)

**Rows that change no code are not re-measured** (default `"all"`): when a commit changes only `notes/`
relative to the tree it is based on (or is an empty commit), and that tree has a KEEP that passed
correctness, carries a gate-window reading and ran on the same cluster, the driver runs no eval / NCU and
archives the row with that KEEP's reading (the status row's `reading_of` = the iteration of the row the
reading belongs to). `[loop]
reuse_unchanged_reading = "gate"` applies only to gate rows; `"off"` re-measures every row (the old
behaviour). (Why: gate rows submitted on their own, decisions re-reported unchanged and rows that only
price make up a sizeable share of the iterations, and each eval of such a row reads the same tree; the
extra readings are just noise samples, and the patch ruling and the best take the largest of them.)

**`[CLOSES: M<k>-gate]` finish** (on by default): when a delivery after green carries this tag in its
change and the whole-machine eval KEEPs it, the driver immediately archives the `M<k>-gate` row from
the same tree and the same reading (a separate row; phase-close, the same-phase gate regression check,
the M0 audit after a reopen and the timeline all read it as usual), saving the round in which the
student would submit the gate row on its own + the smoke probe + the eval. Not archived for build-phase
rows, an unfinished `part k of n`, or while the placeholder ledger is not cleared (the student then
submits it on its own as before).
`[loop] declared_gate_close = false` turns it off.

**Job environment: the start preflight and `job_env_files`.** The driver's own channels (each round's
NCU, timeline, stall ledger, pricing round) all run in the jobs of the student's operator tree, and the
tree must satisfy two things: `gpu_entry.sh` makes a **bare `python3`** in the job point at an
interpreter with torch (jobs on an ssh remote run in a non-login shell, and the image's venv is not on
PATH — driver tools are started as `python3 notes/<tool>.py`, which then spawn `python3 eval/bench.py`);
the profiler window of `eval/ncu_run.py` uses `torch.cuda.profiler.start/stop` (cuda-python 13 has only
`cuda.bindings`, no `cuda.cudart`).

- `job_env_preflight` (default `"refuse"`): on every start (including resumes), before the iterations,
  run two short jobs — the driver-seeded `notes/job_env_check.py` (can a bare `python3` import torch)
  and this tree's NCU job (exactly as every round's eval submits it). Only job **environment** failures
  count (`ModuleNotFoundError` and the like; a scaffold kernel throwing does not); on failure the start
  is refused, exit code 13. `"warn"` only warns and runs anyway, `"off"` does not run them.
- The same kind of failure during the run prints `ENV-BROKEN <channel> (xN in a row)`: NCU is no
  longer retried (a retry would only reproduce the same import error), the pricing round does not
  reopen the design turn for it, and the failure rows of timeline / stall say it was the job environment.
- `job_env_files` (default empty = off): the tree's job-environment files (relative to the tree
  directory; not the kernel file and not `notes/`). Every time the driver pushes a job branch it layers
  the tree's **current copy** on top as a temporary commit; the student lineage and the recorded sha
  are unchanged. If a running run finds the environment broken, fix the file in the tree and the next
  job picks it up. The student lineage takes only the student's commits, and rollbacks and meta resets
  wash away any fix put in by hand or by the teacher, so this is the only channel for fixing the
  environment. New trees should set
  `job_env_files = ["gpu_entry.sh", "eval/ncu_run.py"]`.

(Why: an observed failure mode — the tree's `ncu_run.py` hard-imported `cuda.cudart` and `gpu_entry.sh`
did not put the venv on PATH, so every NCU / timeline / stall-ledger run of the whole run died on the
import, with logs saying only "ncu empty -> retry", "base-bench-failed-or-incorrect", "job returned no
ledger"; the teacher fixed the environment three times: once it was washed away by the pricing round's
reset, once it stayed on a verdict-probe branch, and once it was made in a tree directory no job ever read.)

**The evaluator belongs to the operator tree: `harness_guard`** (default `"revert"`). `gpu_entry.sh`,
`eval/`, `ref_bin/` and `.gitattributes` are the tree's evaluator (the kernel file and `notes/`
excepted). Two layers, neither relying on the agent sandbox:

- **Job overlay**: in every job tree these files are replaced by the ones **tracked** in the operator
  tree (byte for byte, binary blobs and the sealed reference included), and evaluator files the
  operator tree does not have are deleted from the job tree; the same channel as `job_env_files`, so the
  student lineage and the recorded sha are unchanged. The tree directory must be a git repo (the tracked
  list is read from it; the gitignored key never enters a job tree).
- **Driver path check**: as soon as one delivery (including this iteration's probe commits) changes an
  evaluator file, it is not evaluated but REVERTed straight to the start of this iteration, and the
  record names which files were changed; before each iteration starts, evaluator files in the lineage
  that deviate from the starting tree (probe commits left by an iteration that ended without a record,
  files the teacher's turn left in the working directory) are restored in one separate commit.

At start the working directory's HEAD is compared with the tree's evaluator: a fresh start with a
mismatch is refused (exit code 19), a resume only warns (later jobs all run the tree's copy, so readings
before and after may not be comparable). `"warn"` only logs and does not REVERT (the job overlay still
applies), `"off"` turns everything off.

**Precision gate: `precision_contract`.** A tolerance (`|d| <= atol + rtol*|ref|`) cannot tell "an
honest kernel that rounds in different places" from a kernel that "drops fp32 accumulation to bf16 /
turns on tf32 / quantizes inputs to fp8": at 1e-2 both pass. The precision gate looks at the **error
ratio**: the reference (the definition's PyTorch implementation, also used for a sealed reference) is
re-run in float64 as ground truth (float inputs and every float type conversion inside it are promoted
to float64; if that cannot run, it falls back to float32; if neither works, it records `unavailable`
with the reason), the kernel and the reference itself each get a relative L2 error `e_cand` / `e_ref`,
and `e_cand > 3*e_ref + max(1 ulp(output dtype), 2^-17)` fails (calibrated on B200, see `eval/precision.py`).
Same job, same batch of inputs: measured in both the correctness and the all modes.

- `strict`: a failure is REVERTed as a correctness failure, and the record says it was the precision
  gate and gives the error ratio. **Default strict for trees with their own bench.**
- `official`: recorded only (the top-level `precision` block of the job JSON, the run log, the
  iteration record's `precision` field), never blocks.
- `off`: not read. **Default off for leaderboard trees** — a leaderboard is judged by the
  leaderboard's rules: `eval/leaderboard.py` matches the official evaluator exactly, does no float64
  recompute, runs no stressed inputs and emits no `precision` block; the driver does not warn and the
  SASS check does not report.

To measure on a leaderboard tree, write `"precision_contract": "official"` (or `"strict"`) in
`eval/leaderboard/problem.json`: `eval/leaderboard.py` recognizes only this key (copy in
`eval/precision.py`; do not edit it), the loop reads it by default as well, and `[loop]
precision_contract` can override it. When the loop wants strict / official but problem.json has not
turned it on, the bench measures nothing: strict refuses a fresh start (exit code 20), the others only
warn. A tree with its own bench calls `precision.PrecisionRecorder` on the
same batch of inputs it grades (usage in the header of `eval/precision.py`) and puts
`prec.block()` into the eval JSON's top-level `precision`; inputs are `snapshot`ted before the
reference / kernel runs, and the ground truth is computed from the pristine inputs `restore`d from it
(otherwise a definition that rewrites its inputs in place would take the modified inputs as ground
truth). Under strict, with the bench not wired up
(no `eval/precision.py`, or `eval/bench.py` never calls `PrecisionRecorder`): a fresh start is refused
(exit code 20), a resume only warns, and at run time `unreported` is recorded; writing `official` /
`off` is the knowing escape hatch. With the bench wired up but an
eval that brings no `precision` block (the kernel and the bench share a process, so the kernel could
turn the measurement off), strict REVERTs it as a correctness failure;
`FK_PRECISION=0` is read only once, when the bench is imported; the kernel changing it later has no effect.

**Stressed inputs** (part of the precision gate): a leaderboard tree with the precision gate on also
measures precision once more on every timed workload with each of a set of stressed inputs —
`offset` (normal sample +1), `spikes` (0.1% of elements set to ±12), `amp` (×4). Only float inputs that
are pure normal samples are touched (heuristic tensors, workload files, custom and fp8 inputs are left
alone); seeds are fixed and the RNG state is restored, so the official sampling sequence is unaffected.
Stressed rows go only into the precision record and **never into the correctness verdict**: under
official the correctness verdict matches the official evaluator; under strict an error-ratio failure on
a stressed row is REVERTed too. Rows where the reference itself is not finite on the stressed inputs
record `unavailable` (the stress blew up the dtype; not the kernel's fault). A tree with its own bench
uses `precision.stress_tensor` to decide for itself which inputs may be stressed.

**SASS precision check** (warning only): each round's orchestration census includes the kernel's MMA
input / accumulation precision (`mma_precision`) in ORCH-SUMMARY; the driver compares it with the
reference's dossier (only those produced by recon / pricing after the field existed have it) and with
the tree's input dtype, and on a reduction prints `WARNING SASS precision` and records it in the
iteration record's `precision.sass`; it never REVERTs, and does not report when
`precision_contract = off`.
For tcgen05 (`UTC*MMA`) the kind lives in the instruction-descriptor register: statically only the
family can be read (`UTCHMMA` = the f16 / bf16 / tf32 class, `UTCQMMA` = f8f6f4), not the
accumulation precision.

**Correctness monitor: `correctness_monitor`** (default `"best"`). After the finish confirmation, a
monitor job runs on the confirmed sha: the tree's own `correctness` task runs once with new seeds and
once with perturbed inputs, while watching the kernel output for NaN/inf and whether two runs on the same
input agree. The tree needs to do nothing; for trees with a `cardref` task, failures on perturbed
inputs can also be compared against the reference. The results are recorded only
(`correctness_monitor.jsonl`, `best_confirmation.json`) and change no verdict; `"off"` turns it off,
`correctness_monitor_profiles` changes the profile list. See
[`docs/correctness-monitor.md`](../../docs/correctness-monitor.md).

The output of `ref_cmd` must yield a recognizable median latency: `median_ms` (or `ms`/`latency_ms`…)
in JSON, or a line `median 2.3641 ms`. If several backends are reported, **the fastest is taken** as
the ref.
`ref_ncu_cmd` is optional, but **without it the milestone cannot write NCU-anchored
mechanism-verification lines** (template A.4).

### When the reference itself also runs in the student job: `ref_in_job = true`

In a run whose reference is measured through a separate submission tree (`ref_mode` / `submit_op`),
the single-ref contract discards, as a stand-in, any comparison object the bench happens to time in
the student job. But in many runs the reference is baked into the image (deep_gemm, FA, cuDNN…), and
the `ref_*` keys in bench.py hold exactly the reference itself — a reading on the same card in the same
minute, the only node-matched comparison in the whole run. Then declare:

```toml
ref_in_job = true    # the ref_* in the bench is the reference itself: keep the same-job reading and judge parity by it
```

Effect: ① `vs_ref_device` (device basis) / `vs_ref` (e2e basis) go into status.jsonl; ② when a round's
KEEP has a same-job ratio ≥ `--equivalence-ratio`, the driver measures that sha in 2 more jobs, and
if the median still meets the bar it is stop=target (recorded in
`paired_verdict.jsonl`); ③ the ghost-gap check at plateau entry re-measures the best on the same card
and reads the ratio instead, no longer buying a BATCH reference job for a cross-node drift conversion,
and the residual the diagnosis gets is `1/ratio − 1`. The separate submission tree still provides the
launch baseline, the NCU signature, recon and pricing — only the currency of the verdict becomes the
same card's. Why: an observed failure mode — a blackbox run measured the reference on the same card
every round but the readings were discarded; the loop chased, in absolute milliseconds on one class of
node, a target converted from the fastest reference sample on another class of node, and burned
several meta steps treating a few percent of node difference as a student gap; after the stop the
same-card multi-job median reading was at parity. A run whose reference already runs with the student
job (`ref_cmd` without `submit_op`) does not need this switch; a run without a reference that sets it
is told it is ignored.

### Recon: on by default for every distillation run; a source run can turn it off explicitly

Before distillation the teacher runs reconnaissance on the reference binary (NCU/SASS probes, the
orchestration dossier, the stall ledger); the recon tree defaults to
`operators/_recon` and can be redirected with `recon_op` — **the same for blackbox and source runs**.
A blackbox run relies on it in place of the source;
a source run takes it as a second input besides the source:

```toml
recon_op = "_myref"   # teacher-side submission tree (operators/_myref, a git repo of its own, with
                      # gpu_entry.sh's cmd channel); omitted = operators/_recon
recon_op = ""         # a source run turning recon off explicitly = declaring a source-only control run (a blackbox run cannot turn it off)
```

When a source run's default tree does not exist, the loop only warns and skips recon (the teacher
falls back to reading the source only), it does not refuse to start; if you want it, create the tree
or write `""` explicitly. Why it is on by default: reference sources are often templated — tile /
stage / warp roles are only given as interfaces, and the source never states the SASS-level issue
order, the barrier topology, or the real smem/register usage. An observed failure mode: a source-only
run filled these in by derivation, derived a run-time split decision and a ping-pong phase, and its M0
was tens of percent slower than the reference; a blackbox run on the same operator with recon measured
these quantities, and its M0 landed in one go at the ratio the source run took dozens of rounds to
climb to. "Source only" is therefore a weakened run, fit only to serve as a control.
The recon tree and `ref_price_op` may be the same tree; recon products are readable only by the
teacher, and the freshstart gate likewise refuses reports left by a previous run.
