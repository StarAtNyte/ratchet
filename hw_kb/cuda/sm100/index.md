# SM100 (Blackwell) interface index — CUDA mode

The sm100 tree of CUDA mode (single-file CUDA C++ student). Demand-driven: a recipe is written when the student gets stuck on that interface,
following `../TEMPLATE.md` (examples are CUDA C++ / CUTLASS (CuTe C++) / inline PTX), and is marked ✅ on **only** one of the two kinds of
evidence below. This file is not a plan; it is the ledger of what has already been earned.

Two kinds of evidence earn ✅, nothing else does. **A GPU probe returning `PROBE PASS`** is the default kind. The second exists because some
knobs are **numerically invisible** — descriptor modes, cache-policy bits, DEPBAR depth: both spellings compute the same bytes, and a `max_diff`
probe cannot see such a change. For this kind, **a shipped KEEP whose own NCU census shows the contract axis moved** certifies it,
citing the axis readings before and after the change and the gate-window readings.

This tree is fully separate from the CuTe DSL mode's `hw_kb/cutedsl/sm100/`: entries there teach the `cute.*` spelling and their readings were taken on the DSL spelling,
so they are not copied over as they are. A batch of the mechanism entries in the table below were rewritten for the same hardware mechanism in CUDA C++ / inline PTX and re-certified
one by one on a CUDA probe — the readings and conclusions in those entries are CUDA measurements, and where they disagree with the DSL side, this tree wins. **Not finding something here does not mean it cannot be done** — for interface details, the local CUDA / CUTLASS headers, the PTX ISA and
your own probes are authoritative; what you win on a probe gets written in here in the finish round.
